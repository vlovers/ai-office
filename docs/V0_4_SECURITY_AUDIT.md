# v0.4 security audit and hardening

Audit baseline: PR #7 at `6353783a97bfddd9ac2404a35257363388609cd7`, compared with `main` / `0f7944e01e7e0db4cdf0b8d31017d185c24651c5`. The baseline GitHub Actions run [39070478525](https://github.com/vlovers/ai-office/actions/runs/39070478525) passed. This audit inspected the complete PR, session/provider lifecycle, persistence, HTTP/SSE and UI surfaces, tests, native policy and optional real-write script. Reproductions used disposable Git repositories, synthetic secrets and databases; no developer project was used as a destructive fixture.

Severity reflects this single-user application's data-loss and host-execution risks. None of the findings establishes an unauthenticated remote exploit. Local API clients are already within the trusted OS-user boundary.

Additional hardening: host verification is now disabled unless the operator sets `AI_OFFICE_ALLOW_HOST_VERIFICATION=1`; the UI shows argv and warns that AI-edited scripts have full host/network access. Requests need an explicit host acknowledgement. This narrows a documented trust boundary; it does **not** make host verification sandboxed. Private workspace identity is persisted without transcript redaction; only output/public responses are redacted. Write resume refuses manually advanced HEAD without resetting it. Root allocation uses exclusive directory creation after recording intent.

The expanded native probe exposed another policy detail during implementation: a nested directory-only deny glob did not deny a child metadata file in the installed macOS runtime. Explicit descendant patterns were added and the full probe then passed, including future nested metadata-directory creation, outside symlinks and both execution modes. Linux deny-glob snapshots have different timing limits; see the [official permissions documentation](https://learn.chatgpt.com/docs/permissions). Tests do not establish a general sandbox proof.

## Deliberately retained boundaries

Only trusted single-user local development is supported. Same-user malicious processes, filesystem replacement during an operation, externally detached processes, machine-managed runtime configuration and OS/kernel compromise are outside the isolation guarantee. Do not edit a worktree during confirmation/cleanup. Filesystem metadata revisions are not immutable content-addressed snapshots. Worktrees share objects/refs and are not containers. Host verification is an explicit escape from agent isolation and must not run unreviewed scripts. Known-path denies/redaction are not a general secret scanner.

Unknown resources, missing ownership fingerprints, stale locks, interrupted operations, ignored user data, nested repositories, advanced HEAD and large ownership scans require manual preservation/inspection. See [workspace recovery](WORKSPACE_RECOVERY.md). There is no automatic merge, reset, push, branch deletion or recovery cleanup. The optional real SDK smoke consumes allowance; it is not normal CI and requires separate approval. Its failed-run fixtures are now retained for inspection.

See [verification evidence](VERIFICATION.md) for actual executed results and CI links. The original green CI did not detect these issues; the added regressions and native policy job are intended to prevent recurrence.
