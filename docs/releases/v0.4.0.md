# AI Office v0.4.0 — release candidate notes

Prepared for review; not published. The package and lockfile use `0.4.0` consistently with the existing semantic-version release labels. The application remains private to npm publication (`private: true`). No release tag is created by this preparation.

AI Office adds a local review workflow for delegated coding tasks. Confirmed write sessions run in their own Git worktree and branch. Inspect Git-derived file changes and readable diffs after the agent exits, optionally run explicitly authorized verification, then Keep or Reject. Kept work stays isolated for manual integration; Reject preserves the branch and refuses ambiguous or committed changes.

Read-only tasks remain the default. Existing queue, streaming, session stop/resume, keyboard navigation and reduced-motion behavior are retained. Only Codex is supported.

## Setup and compatibility

Use Node.js 24.x, `/usr/bin/git`, pinned Codex SDK and CLI **0.162.1**, and existing ChatGPT CLI authentication. `npm` scripts select the locally installed CLI; launching Node directly may select another CLI from PATH. Unsupported versions fail closed. No API key is required for local login and there is no API billing fallback.

Configure the authorized root to contain the source checkout and its common Git metadata. Configure a separate workspace root outside existing Git checkouts. Existing branch/worktree collisions fail safely. See [setup](../V0_4_DEMO.md) before enabling writes.

## Experimental features and boundaries

- Single-user loopback application on a trusted workstation; not a multi-user service or a container/VM boundary. macOS native policy has executed successfully; Linux native isolation remains unverified.
- Codex model inference sends task context to the provider and consumes the selected account's allowance/credits. Local-first describes storage and workflow, not offline inference.
- Native restrictions protect the primary checkout, Git metadata and known sensitive paths. They do not guarantee every possible secret filename is detected. Linux deny-glob snapshots/depth bounds have additional limits documented in the security model.
- Host verification is disabled by default. Enabling it executes configured commands with host permissions and network access. Review AI-edited scripts before authorizing them. Execution is bounded; independently detached programs can escape process-group cleanup.
- Review revisions detect many changes, but do not provide an atomic filesystem snapshot. Stop external edits during review decisions.
- Unknown/replaced worktrees, stale leases and interrupted cleanup require manual diagnosis. No automatic destructive recovery. Preserve work before intervening.
- SQLite schema v5 is not compatible with older binaries. Back up application metadata before upgrading; retain repositories/worktrees separately.
- No automatic merges, force-pushes, branch deletion, package publication or releases.

## Verification and release decision

See [current release evidence](../V0_4_RELEASE_VERIFICATION.md), [security audit](../V0_4_SECURITY_AUDIT.md), [security model](../SECURITY.md) and [workspace recovery](../WORKSPACE_RECOVERY.md). The approved two-turn real Codex write workflow passed on macOS: Git review, bounded verification, Keep/Reject, primary-checkout preservation and persisted decisions across backend restarts. Recorded usage was 57,719 input tokens (42,496 cached) and 153 output tokens on gpt-6.1-sol through existing ChatGPT login. All local automated gates and PR validation passed; the current-head CI links are tracked in the PR. These results support an initial experimental macOS release within the documented boundaries, and do not attest Linux native isolation or abrupt-kill real-model recovery.
